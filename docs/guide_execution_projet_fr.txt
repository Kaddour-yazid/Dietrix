GUIDE D'EXECUTION DU PROJET DIETRIX / DIETTRICKS

1. OBJECTIF DU PROJET

Ce projet est une application locale de planification alimentaire et sportive.
La version active du projet utilise uniquement :

- frontend/       -> interface utilisateur en React + Vite + TypeScript
- backend_api/    -> API en Flask + base de donnees SQLite

Les dossiers `secure_app/` et `insecure_app/` existent dans le depot, mais ce ne sont pas les applications principales a lancer pour la version finale actuelle.


2. PRE-REQUIS

Avant d'executer le projet sur Windows, il faut installer :

- Python 3
- Node.js
- npm
- PowerShell

Remarque :
- npm est normalement installe automatiquement avec Node.js.
- SQLite n'a pas besoin d'etre installe manuellement, car le projet utilise la bibliotheque SQLite integree a Python.

5. CREATION DE L'ENVIRONNEMENT PYTHON

Depuis la racine du projet, executer :

```powershell
py -3 -m venv .venv
```

Cette commande cree un environnement virtuel Python dans le dossier `.venv`.


6. ACTIVATION DE L'ENVIRONNEMENT VIRTUEL

Dans PowerShell, executer :

```powershell
.\.venv\Scripts\Activate.ps1
```

Si PowerShell bloque l'execution des scripts, lancer d'abord :

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Puis relancer :

```powershell
.\.venv\Scripts\Activate.ps1
```

Quand l'environnement est actif, vous verrez generalement `(.venv)` au debut de la ligne de commande.


7. INSTALLATION DES DEPENDANCES PYTHON

Toujours depuis le dossier racine du projet, executer :

```powershell
py -3 -m pip install -r requirements.txt
```

Le fichier `requirements.txt` contient ici la dependance principale suivante :

- Flask==3.1.0


8. INSTALLATION DES DEPENDANCES FRONTEND

Toujours depuis la racine du projet, executer :

```powershell
cmd /c npm run frontend:install
```

Cette commande installe les dependances du dossier `frontend/`.

15. CONFIGURATION OPTIONNELLE DE L'IA LOCALE

Le projet peut fonctionner sans intelligence artificielle.
La partie IA est optionnelle.

Si vous voulez que le projet utilise reellement Ollama, il faut :

1. Installer Ollama
2. Telecharger un modele
3. Creer un fichier `.env`
4. Lancer Ollama avant le backend
5. Enregistrer le profil d'un utilisateur dans l'application

15.1 Installer Ollama sous Windows

Telecharger Ollama ici :

https://ollama.com/download/windows

Installer normalement le programme.

Pour verifier l'installation :

```powershell
ollama --version
```


15.2 Telecharger un modele

Commande exemple pour telecharger le modele utilise par le projet :

```powershell
ollama pull deepseek-r1:1.5b
```

Pour verifier que le modele est bien disponible :

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:11434/api/tags
```


15.3 Creer le fichier `.env`

Creer ensuite un fichier `.env` a la racine du projet a partir de `.env.example`.

Contenu exemple :

```env
OLLAMA_ENABLED=1
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=deepseek-r1:1.5b
OLLAMA_TIMEOUT_SECONDS=120
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4o-mini
```

Explication :

- `OLLAMA_ENABLED=1` active l'utilisation d'Ollama
- `OLLAMA_BASE_URL` indique l'adresse locale du service Ollama
- `OLLAMA_MODEL` indique le modele a utiliser
- `OLLAMA_TIMEOUT_SECONDS=120` laisse plus de temps au backend pour attendre la reponse du modele


15.4 Demarrer Ollama

En general, Ollama se lance automatiquement apres l'installation.
Sinon, ouvrir Ollama depuis le menu Demarrer de Windows.

Pour verifier que le service repond :

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:11434/api/tags
```


15.5 Comment le projet utilise Ollama

Dans ce projet, Ollama est utilise par le backend Flask.

Le fonctionnement est le suivant :

- l'utilisateur cree un compte
- l'utilisateur remplit son profil
- au moment de la sauvegarde du profil, le backend contacte Ollama
- Ollama aide a personnaliser le plan genere
- si Ollama ne repond pas, le projet continue avec le mode normal sans IA

Autrement dit :
- le projet fonctionne sans Ollama
- mais si Ollama est actif, il est reellement utilise au moment de l'enregistrement du profil


15.6 Comment verifier que le projet utilise vraiment Ollama

1. Lancer Ollama
2. Lancer le backend
3. Lancer le frontend
4. Ouvrir l'application
5. Creer un compte
6. Remplir et sauvegarder le profil

Si Ollama fonctionne correctement, le backend utilise le modele local pour enrichir le plan.

Remarque importante :
- avec le modele `deepseek-r1:1.5b`, la sauvegarde du profil peut prendre environ 1 minute
- cela depend de la vitesse de la machine

Cette partie reste facultative. Le projet fonctionne meme sans fichier `.env` ou sans Ollama, mais dans ce cas il utilisera le mode local standard sans IA.


16. PROBLEMES FREQUENTS ET SOLUTIONS

Probleme 1 : `py` n'est pas reconnu
Solution :
- verifier que Python est bien installe
- redemarrer le terminal
- reinstaller Python en cochant "Add Python to PATH"

Probleme 2 : `node` ou `npm` n'est pas reconnu
Solution :
- installer Node.js
- fermer puis rouvrir PowerShell

Probleme 3 : erreur lors de `Activate.ps1`
Solution :
- executer :

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Probleme 4 : le frontend ne s'affiche pas correctement
Solution :
- verifier que le backend tourne sur `http://127.0.0.1:5002`
- verifier que le frontend tourne sur `http://localhost:5173`
- actualiser avec `Ctrl + F5`

Probleme 5 : le port 5173 ou 5002 est deja utilise
Solution :
- fermer les anciens processus
- relancer le projet
- pour le frontend, Vite peut automatiquement changer de port
